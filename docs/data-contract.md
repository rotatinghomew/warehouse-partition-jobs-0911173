# 离线作业时间语义

源分区的day属于地区业务日，不一定等于UTC自然日。事件原始时间必须含时区。地区日区间转换到UTC后可跨两个UTC日期。配置中的全国周口径为UTC周一零时至下周一零时；地区日汇总保留本地日期，全国周从统一时间边界选择来源，不把同名day直接拼接。

源分区修订表示同一地区业务日的一份完整更正，不与前版逐行叠加。相同内容重传不分配新版本号，但会在 `source_deliveries` 追加一次交付记录，用于区分首次到齐与同内容重传。现有显式日周运行API用输入参数指定计算，run_week检查调用者提供的日期范围；自动分区依赖与并行执行者协调由 `plan.py`、`runner.py` 在其上层实现。历史已命名发布不改写；日常消费者读取的当前完整结果通过 `current_entries` 原子向前推进，封存发布（releases）与当前结果（current_entries）是两套互不覆盖的名称空间。

补算运行（runs/run_steps）把计划时刻的源版本固定在 pins 中：步骤内容寻址、可重试、可恢复；切换前逐分区核对 pins 未被更新版本超越，超越时运行转为 superseded 并拒绝发布。backfill 与 daily 是两种运行类型，前者只能处理历史业务日并在计划与切换两个时刻核对边界，后者只能处理各地区当前业务日且不生成周步骤。当前条目按 (scope,key) 保存 payload、pins、fence 与 run_id；fence 单调递增，切换用比较 fence 的 CAS 写入，两个执行者同时完成相同工作时后到者不会用较旧 fence 覆盖。`current_snapshot` 校验同一业务周的日条目与周条目属于同一次切换，否则视为未形成一致快照。

血缘方向覆盖输出到源：日结果对应单一源分区版本，周结果对应完整的固定输入版本集合，封存发布通过其周结果追溯到每个源分区版本，并标注该版本是否已被后来的更正超越。地区业务日配置保存在calendar.json。输入记录可保留occurred时间以定位跨UTC周边界的活动，人数总量不能在未掌握事件时间时任意按小时比例切分。
